# Web UI 改善紀錄（2026-10-15）

依全站 critique，按 A → B → C 分階段完成。保留 Desktop、既有 API、共用 Axios，以及獨立的 Chat / Agent 路由與 service。

## A — 手機與鍵盤可及性

- 1100px 以下使用可展開的精簡導覽；提供跳至主內容與 Escape 收合。
- 900px 以下聊天清單與對話切換顯示；分析設定可收合。移除手機聊天清單的固定 500px 最小高度。
- ModelPicker 改用原生 grouped select；圖片及管理員編輯共用原生 dialog，背景 inert、焦點隔離、Escape 與關閉後焦點還原。
- 圖片放大後可用方向鍵平移；閾值、聊天輸入、搜尋補可存取名稱；回覆狀態採完成公告而非逐 token 播報。
- 擴大常用觸控目標並補 reduced-motion 支援。

驗證：`cd web-frontend && npm run build`。以 localhost 隔離示範資料在原生瀏覽器檢查 390×844 與桌面；手機聊天輸入起點由約 2250px 提前至約 737px，沒有文件水平溢出。圖片視窗 Tab 焦點保持於視窗，Escape 返回圖片；管理員編輯 Escape 返回原 Edit 按鈕。這些是 UI fixture 驗證，不代表真實 DB / YOLO / LLM 整合測試。

人工回歸：手機開啟／關閉選單，切換歷史對話；鍵盤操作模型選單；開啟圖片後 Tab / Shift+Tab / Escape / + / - / 方向鍵；管理員編輯關閉後確認焦點還原。

## B — 偵測到分析與失敗復原

- 分析頁用既有 GET API 選取已保存結果／批次，支援分頁、縮圖、檔名與日期；保留 query-param 捷徑及使用者自寫問題。資料未讀取成功或尚未完成時禁止需要資料的分析送出。
- 分析來源顯示可讀連結，工具 JSON 移至技術詳情。Chat 與 Agent 支援停止接收（僅中止前端請求，不承諾停止後端生成）；Chat 送出時立即顯示待回覆問題。
- 批次多圖與資料夾入口分離；超大檔案先提示；批次分頁、失敗原因、模型載入錯誤與重試。輪詢改為等待前次完成後排程，連續三次失敗顯示斷線、最後更新時間與重連。
- 批次刪除顯示範圍並預設聚焦取消；處理中不提供刪除。管理員清單使用既有 API 分頁。
- 登入恢復原生必填驗證；註冊規則持續可見，成功後讓使用者自行返回登入；Profile 暱稱清空文案與實際行為一致。

驗證：build 通過。隔離 fixture 驗證缺少必要資料時按鈕停用、選擇後顯示摘要且保留自寫問題、URL ID 帶入、串流等待／完成狀態；批次刪除確認範圍、Escape 取消與還原焦點；模擬模型 503 後顯示重試，恢復服務並點重試後選單可用。輪詢錯誤計數、退避排程與卸載清理另以原始碼檢查；真實網路與推論流程待整合環境驗證。

## C — 工作流程層級、版面與字級

- 首頁改為開始單張／批次偵測及最近工作；次要功能保留可見入口，移除重複帳號統計。
- 一般頁首縮減為標題／說明，主要任務標籤採中文；偵測設定與影像比較並列，進階閾值可展開。
- Profile 標籤和值分行並支援長文字；管理頁獨立於偵測 history layout，清單先顯示、建立表單改為可展開。
- 調整 muted／淡色表面文字、刪除與分析標籤對比；統一字級、間距、邊框與數字；原生 select 沿用系統字體。
- 使用路由 lazy import，入口 JavaScript 約 263KB（gzip 88.5KB），原本約 504KB 的單一 chunk 不再出現 500KB 警告。這是產物大小比較，不等同實測載入速度。
- 設計規範記錄於 `web-frontend/DESIGN.md`。既有 critique 因來源內容變更由儲存工具標示 closed，歷史分數保留，沒有宣稱新的評分。

驗證：最終 build 通過；10 個路由在 320px、390px、900px 下沒有文件水平溢出，桌面檢視首頁、偵測、Profile、管理頁與對話。320px 展開各類別閾值後仍無文件溢出，欄位名稱包含類別／conf／IoU。合成 PNG 選檔預覽、fixture 偵測回覆、物件表與分析捷徑帶入 ID 通過；獨立 Chat fixture 回覆與 Agent 串流完成通過。各階段視覺檢查採一次檢視、集中修正、一次確認，未作無限調整。

最終機械掃描僅指到既有進度條的 `transition: width`；它已被新規則停用，清理時移除舊宣告。`git -c core.whitespace=cr-at-eol diff --check` 通過（專案部分來源原本使用 CRLF）。

## 驗證範圍與後續

本輪僅使用隔離 UI fixture，不連真實資料庫、不觸發真實 YOLO／LLM，也未部署。真實硬體／Safari／Firefox、完整讀屏與 200% 縮放仍需正式環境驗收。停止接收不等於停止後端作業。跨頁的完整 Agent 歷史、伺服器端檔名／日期搜尋，以及 1000 張批次架構仍屬後續 API／批次階段，未在 UI 改善中擴寫後端。

## 後續 — AI 助理共用入口

- 主選單與工作台將兩個 AI 入口合為「AI 助理」，以具有 `aria-current` 的「一般對話／偵測分析」路由連結切換；兩個頁面、後端端點與 service 保持獨立。
- 路由父層保存兩組分開的草稿、目前對話、模型與分析資料選擇；避免切回一般對話時自動開啟最新紀錄、蓋掉使用者的新對話。一般對話清單排除 Agent 紀錄。
- 僅保存在工作區記憶體。切換仍重新確認分析資料可讀與已完成；手機收合設定後仍看得到分析檔名與 ID。生成中切換會停止前端接收，保留已收內容並標示可能不完整；不能保證後端停止。
- 真實 API／本機模型驗收另見 `web-real-integration-validation.md`；這階段未變更後端、資料表或 Desktop。

驗證：production build、差異空白檢查；以真實後端在原生瀏覽器驗證兩種草稿與不同模型切換保留、分析模式及結果 ID 保留、Chat 舊對話與 Agent 真實串流內容保留、生成中切換中止接收與提示。桌面、390px 與 320px 無文件水平溢出；以 Enter 啟動分頁連結，手機可看到選定資料與輸入框。登出後重新登入、重新整理清除暫存及新對話防自動覆寫均通過；最終重新載入後無新增客戶端錯誤。狀態層另以 Node assertions 驗證 query 初值與設定值相同時仍須保存、兩頁草稿互不影響、清空選擇及連續 functional updates。開發時發現混合匯出 Context 與元件會造成 HMR 的 Context identity 問題，已將狀態層拆至 `state/assistantState.js`。

## 2026-10-16 — 偵測卡片等高、模型分類與閾值換行

依使用者兩張截圖調整：

- 桌面（1100px 以上）設定卡片與原圖／標註卡片一起延伸至同列高度，修正影像卡片提早結束的落差。1100px 以下保留自然高度；900px 以下設定移至影像上方，600px 以下影像單欄。影像既有 `object-fit: contain` 及比例保留。
